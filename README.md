# HyperPack v0.2.8

Windows x64 배포판입니다.

## 핵심 수정

0.2.7의 코드를 비판적으로 검토한 결과 다음 문제가 있었습니다.

1. Win32 UI 메시지 루프 스레드가 명시적으로 고정되어 있지 않았습니다.
2. 작업 상태를 읽는 백그라운드 goroutine이 UI 컨트롤(`SetWindowText`, `InvalidateRect`)을 직접 호출했습니다. 이 구조는 Windows GUI 스레드와 충돌하거나 교착/응답없음 증상을 만들 수 있습니다.
3. `WNDCLASSEXW`의 클래스명 문자열 수명이 명확하게 보장되지 않았습니다.
4. 시작 경로에 오류 추적 로그가 없어 초기화 실패 원인을 확인하기 어려웠습니다.
5. 작업 프로세스와 UI의 역할은 분리되어 있었지만 UI 갱신 방식이 완전히 분리되지는 않았습니다.

v0.2.8에서는 UI 스레드를 `runtime.LockOSThread()`로 고정하고, 작업 프로세스 상태는 UI의 `WM_TIMER`가 읽게 변경했습니다. 작업 프로세스는 결과 파일을 작성한 뒤 `PostMessageW`로 UI에 완료 이벤트만 전달합니다.

## 실행

`HyperPack.exe`를 더블클릭합니다.

문제가 발생하면 `Run_Debug.bat`를 실행해 콘솔 메시지를 확인하거나 `%TEMP%\\HyperPack_startup.log`를 확인할 수 있습니다.

## 기능

- 여러 파일을 하나의 `.hpk`로 묶기
- 폴더 전체를 하나의 `.hpk`로 묶기
- HPK 압축 해제
- Level 0~9
- 대용량 스트리밍 압축/해제
- 압축 작업 별도 프로세스
- 작업 중 GUI 유지
- HPK1/v1 포맷 호환
